# TinyNet.Tests

Тесты фреймворка на xUnit.

[English version](README.md)

---

## Запуск

```bash
dotnet test TinyNet.Tests
```

---

## Что покрыто

Набор намеренно небольшой. Покрывается то, что ломается молча, не воспроизводится руками
или уже ломалось, — а не всё, что умеет фреймворк.

| Файл | Что фиксирует |
|---|---|
| `HttpParsingTests` | Разбор головы запроса; `Content-Length` в байтах |
| `ParameterBindingTests` | Привязку `[FromQuery]` и `[FromBody]` |
| `RequestReadingTests` | Чтение запроса, разорванного по границе TCP-чтений, вплоть до байта за раз |
| `StaticFileTests` | Отдачу файла и отклонение путей за пределы корня статики |
| `DependencyInjectionTests` | Времена жизни и то, что удерживает singleton, зависящий от scoped |
| `OverloadTests` | Настоящий сервер на выбранном ОС порту отвечает `503` при заполненной очереди |

---

## Состояние

Шестнадцать тестов из девятнадцати проходят. Три красных фиксируют привязку query и тела из
раздела **В работе** в [корневом README](../README.ru.md) и будут падать, пока эта работа
не сделана.

## Как добавить тест

`InitControllers` сканирует все загруженные сборки, поэтому контроллеры из
`TestControllers.cs` видны сразу всем тестам, а их `[Route]` обязаны оставаться
уникальными. Новые тестовые контроллеры добавляй в этот файл, а не рядом с тестом.

К `internal`-членам тесты добираются через `InternalsVisibleTo`, объявленный в
`TinyNet.csproj`. Тест, которому нужен работающий сервер, просит порт `0` и читает реальный
из `WebApplication.Port`.
