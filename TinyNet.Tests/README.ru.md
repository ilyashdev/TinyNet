## Что покрыто

Набор намеренно небольшой. Покрывается то, что ломается молча, не воспроизводится руками
или уже ломалось, — а не всё, что умеет фреймворк.

| Файл                       | Что фиксирует                                                                                                                                                                                                                                                         |
|----------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `HttpParsingTests`         | Разбор головы запроса: значения query с `=`, голова, приходящая по байту, отказ на конфликтующие `Content-Length`, `Content-Length` вместе с `Transfer-Encoding`, второй `Host`, голый LF и тело больше лимита; `Content-Length` ответа в байтах                      |
| `RequestReadingTests`      | Настоящее соединение: конвейерные запросы получают ответы по порядку, непрочитанное тело дочитывается перед следующим запросом, chunked-тело, `413` на chunked-тело больше лимита, `408` на недописанную голову                                                       |
| `RequestValuesTests`       | `GetFromQuery<T>` возвращает `null` для отсутствующего значения и бросает исключение с `400` для неразбираемого; `ReadJsonAsync<T>` не зависит от регистра имён и бросает исключение с `400` для неподходящего тела; тело читается один раз, если его не буферизовать |
| `RoutingTests`             | Поиск по пути и методу (литерал против параметра, `404` против `405`, `HEAD` для `GET`-эндпоинта), `400` на нечисловое значение маршрута, порядок фильтров от внешней группы к эндпоинту, `400` на битый JSON                                                         |
| `DependencyInjectionTests` | Времена жизни, то, что `Validate()` ловит singleton, который достаёт scoped через transient, порядок освобождения                                                                                                                                                     |
| `OverloadTests`            | Настоящий сервер отвечает `503`, когда заняты слоты запросов и очередь; простаивающее keep-alive соединение слот не держит                                                                                                                                                                                         |

## Как добавить тест

Маршруты объявляются явно, поэтому каждый тест собирает только нужные ему маршруты.
`TestServer` поднимает настоящий сервер на порту `0` с переданными маршрутами и, если нужно,
настройкой билдера для параметров и сервисов. `SendAsync` шлёт один запрос на соединение,
`SendRawAsync` — сырые байты для тестов протокола. Обработчики пиши лямбдами рядом с тестом,
который их использует.

К `internal`-членам тесты добираются через `InternalsVisibleTo`, объявленный в
`TinyNet.csproj`. Тест, которому нужен работающий сервер, просит порт `0` и читает реальный
из `WebApplication.Port`.
