
## Что покрыто

Набор намеренно небольшой. Покрывается то, что ломается молча, не воспроизводится руками
или уже ломалось, — а не всё, что умеет фреймворк.

| Файл | Что фиксирует |
|---|---|
| `HttpParsingTests` | Разбор головы запроса; битое JSON-тело с JSON-`Content-Type` отклоняется, прочие тела как JSON не разбираются; `Content-Length` в байтах |
| `RequestValuesTests` | `HttpContext.GetFrom…` возвращает `null` для отсутствующего или неразбираемого значения; `ReadFromBodyAsync<T>` не зависит от регистра имён и возвращает `null` для отсутствующего или неподходящего тела |
| `RoutingTests` | Поиск по пути и методу (литерал против параметра, `404` против `405`), базовые пути групп, порядок фильтров, `400` на битый JSON до контроллера |
| `RequestReadingTests` | Чтение запроса, разорванного по границе TCP-чтений, вплоть до байта за раз |
| `StaticFileTests` | Отдачу файла и отклонение путей за пределы корня статики |
| `DependencyInjectionTests` | Времена жизни и то, что `Validate()` ловит singleton, который достаёт scoped через transient |
| `OverloadTests` | Настоящий сервер на выбранном ОС порту отвечает `503` при заполненной очереди |

## Как добавить тест

Маршруты объявляются явно, поэтому каждый тест собирает только нужные ему маршруты.
`TestServer` поднимает настоящий сервер на порту `0` с переданными маршрутами и шлёт один
запрос на соединение. Тестовые контроллеры держи рядом с тестом, который их использует.

К `internal`-членам тесты добираются через `InternalsVisibleTo`, объявленный в
`TinyNet.csproj`. Тест, которому нужен работающий сервер, просит порт `0` и читает реальный
из `WebApplication.Port`.
